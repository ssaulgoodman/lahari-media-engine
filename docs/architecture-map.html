Known Weakness: Shot Prompt Continuity
  • writeShotPrompts batches shots in groups of 15. Shots at batch boundaries have no context of adjacent batch prompts.
  • No explicit instruction to Claude about shot-to-shot visual continuity within a batch.
  • Each shot is described as an island — Claude may infer sequence from order but isn't told to maintain flow.
  • Text prompts and image generation are disconnected — Claude writes all 44 prompts without knowing what images will result.

Character/environment locking is optional — user clicks "Proceed" when satisfied.
Unlocked characters/environments get auto-resolved during image generation.

Scenes are independent — can work on multiple scenes in parallel.
Shots within a scene are sequential — shot N+1 needs shot N locked.

Scene 1 Shot 1 ← style + char refs + env ref (no continuity ref) Start frame → End frame → Lock | end frame passes down as Image ref ↓ Shot 2 ← style + char refs + env ref + Shot 1 end frame Start frame → End frame → Lock | end frame passes down ↓ Shot 3 ← ... (continues sequentially) Scene 2 (independent, can run in parallel) Shot 1 ← style + char refs + env ref (no continuity from Scene 1) ...
Known Weakness: Image Continuity
  • Continuity is image-only (pixel reference) — the text prompts don't carry continuity cues between shots.
  • Cross-scene continuity is absent — Scene 2 Shot 1 has no reference from Scene 1's last shot.
  • The image model may receive conflicting signals: text prompt says "wide shot" but continuity ref is a close-up face.

Shot Start Frame — Reference Index

Image 1 = Character: Kolasura ← cast_members.reference_asset_id Image 2 = Character: Mahalakshmi ← cast_members.reference_asset_id Image 3 = Style reference ← projects.style_asset_id Image 4 = Environment: Vaikuntha ← environments.reference_asset_id Image 5 = Last-scene continuity reference ← prev shot's end_image_asset_id PROMPT Scene: {visualPrompt} Style: {styleDNA} Preserve character identity. Match environment. Continue visual flow. Anti-slop: No AI/CGI look, no excessive detail, no generic fantasy.

End frame receives: start frame (Image 1) + style ref (Image 2) + scene + motion + style DNA.

1
transcribeLyrics + detectStructure (×2 parallel)

In: audio file → Out: lyrics + musical structure
Stored: projects.lyrics, musical_structure
2
summarizeMeaning (sequential, needs lyrics)

In: title + language + lyrics + context → Out: prose meaning summary
Stored: projects.meaning
Text-only — does not re-send audio
3
generateConceptOptions
Claude Opus (tool_use)
In: title + lyrics + meaning + structure + context → Out: 3 concept options
Stored: projects.concept_options → user locks → projects.locked_concept
4
planScenes
Claude Sonnet (tool_use)
In: concept + lyrics + structure + meaning → Out: cast[] + environments[] + scenes[shots[]]
Stored: cast_members, environments, scenes, shots (direction placeholders)
5

Claude Opus (tool_use)
In: concept + lyrics + meaning + script summary → Out: 4 style directions (title + description)
Not persisted (client state only)
User can re-brainstorm even after locking a style
6
generateSingleStyleImage (×N user selects)
Gemini 3 Pro Image Preview
In: style direction text + subject → Out: style image
Stored: assets (category: style)
7
enrichStyleDNA
Claude Sonnet (vision)
In: locked style image + short desc → Out: 30-50 word keyword DNA
Stored: projects.style_description, style_asset_id
Keywords only, not prose. Injected directly into image gen prompts.
8
generateCharacterLooks (×N characters, 3 variants each)
Gemini 3 Pro Image Preview
In: char desc + style DNA + style image ref + feedback → Out: 3 look images (same prompt, pick best)
Stored: assets (character) → user locks → cast_members.reference_asset_id
Currently 3 separate calls. TODO: 1 call returning 3 images + parallel across characters.
9
generateEnvironmentLooks (×N environments, 3 variants each)
Gemini 3 Pro Image Preview
In: env desc + style DNA + style image ref → Out: 3 look images (same prompt, pick best)
Stored: assets (environment) → user locks → environments.reference_asset_id
Same TODO: 1 call returning 3 images + parallel across environments.
10
writeShotPrompts (batch of 15)
Claude Sonnet (tool_use)
In: script skeleton + style DNA + char descs + concept + lyrics → Out: visualPrompt + motionPrompt per shot
Stored: shots.visual_prompt, shots.motion_prompt
No shot-to-shot continuity instruction. Batch boundaries break context.
11
generateShotFramePair or separate start + end (×N shots)
Gemini 3 Pro Image Preview
In: visualPrompt + motionPrompt + char refs + style ref + env ref + prev end frame → Out: start + end frame images
Stored: shots.image_asset_id, shots.end_image_asset_id
Frame pair: single call for both. Falls back to 2 calls if model returns 1 image.
12
generateVideo (×N shots)
Veo 3.1
In: start keyframe + end keyframe + motion prompt + scene context → Out: video clip (MP4)
Stored: assets (shot_video) + shots.video_asset_id

Data Flow

Audio File ↓ [Gemini × 2] → lyrics, structure → projects table ↓ [Sonnet] → meaning (text-only, no audio) → projects.meaning ↓ [Opus] → 3 concept options → user picks → locked concept → projects.locked_concept ↓ [Sonnet] → cast + environments + scenes + shots → 4 tables ↓ [Opus] → 4 style text directions → client state ↓ [Gemini Pro Image] → style images → user locks → [Sonnet vision] → 30-50 word style DNA → projects.style_* ↓ [Gemini Pro Image] ×3 per character → user locks → cast_members.reference_asset_id [Gemini Pro Image] ×3 per environment → user locks → environments.reference_asset_id ↓ [Sonnet] → visualPrompt + motionPrompt per shot → shots.visual_prompt, motion_prompt (no continuity between shots at text level) ↓ [Gemini Pro Image] → start + end frame (pair or separate) → shots.image_asset_id, end_image_asset_id user locks → shots.locked = 1 → end frame passes to next shot as image ref (image-only continuity, no text continuity) ↓ [Veo 3.1] → video clip → shots.video_asset_id ↓ [FFmpeg WASM] → final rendered video → client download
