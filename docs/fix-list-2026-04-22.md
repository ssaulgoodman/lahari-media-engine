# Fix List — 2026-04-22

Compiled from full review session. Fix all before Storyboard.tsx frontend breakup.

## Critical Bugs

### 1. Stale generation_prompt ignored on regen
**Where:** `server/routes/generate-looks.ts` lines 60-69 (character), 261-270 (environment)
**Problem:** Code checks `if (!genPrompt)` to decide whether to rebuild the prompt template. But when `prompts_stale` is true (style changed, description changed), it still reuses the old prompt — which may contain old style DNA text or outdated descriptions.
**Fix:** When `member.prompts_stale` or `env.prompts_stale` is true, null out `genPrompt` and rebuild from template. Clear the stale flag after rebuild.

### 2. Character/env unlock doesn't show previous candidates
**Where:** `components/AnalysisEditor.tsx`, `App.tsx`
**Problem:** Look candidates (the 3 generated options) are stored only in React state (`lookCandidates`). Once you lock one and navigate away, the other options are lost forever. There's no "unlock" that lets you see the alternatives again.
**Fix options:**
- A) Persist look candidates as assets in DB (category `character_candidate` / `environment_candidate`) with the member/env ID. On unlock, query them back.
- B) Simpler: on "unlock look", just re-generate 3 new candidates. The locked one stays until a new one is explicitly picked.
- Recommendation: B is simpler and matches the concept unlock pattern (unlock → browse → re-lock).

### 3. Character phase unlock button broken
**Where:** `components/AnalysisEditor.tsx` line 1940
**Problem:** `onUnlockCharacters` only shows when `project.status === 'characters_locked'`. If status moved past characters (to environments_locked or in_production), the button disappears. Same root cause as the concept unlock bug we fixed — `isLockedPhase` was using data presence, not status. We fixed it for concept but the unlock buttons for characters/environments have their own conditional: `project.status === 'characters_locked'`.
**Fix:** These unlock buttons should show when the phase is locked per status, not just when status equals exactly that value. Use a `canUnlock(phase)` check instead of exact status match.

### 4. Start button still blocks on audio download + SRT
**Where:** `server/routes/queue.ts` lines 105-143
**Problem:** Audio download (line 105), SRT download (line 128), and lyrics transcription (line 138) all happen synchronously before the response is sent. The Gemini transcription can take 10-20s. The "instant navigation" only applies to structure+meaning analysis, not the audio/lyrics step.
**Fix:** Create the project immediately with just title + queue link. Move audio download + SRT + transcription to the background async block alongside structure + meaning. Frontend already polls for completion.

### 5. Refine-script path doesn't calculate per-shot durations
**Where:** `server/routes/generate-script.ts` line 307
**Problem:** `duration: shot.duration || project.target_duration || 8` — flat value for every shot. The first-gen path (lines 110-131) properly calculates remainder for the last shot using ceil. The refine path skips this entirely.
**Fix:** Apply the same ceil + remainder logic from the first-gen path to the refine path.

## Pacing / Duration

### 6. Tell Claude the minimum shot duration
**Where:** `server/services/claude.ts` — planScenes + refineScript prompts
**Problem:** A 6s Intro scene gets a 6s shot, but Veo Fast can only generate 8s. The video model's minimum duration should be a constraint Claude knows about.
**Fix:** Add to the prompt: `Minimum shot duration: ${minDuration}s. No shot can be shorter than this — adjust scene boundaries if needed.` Pass the model's smallest valid duration alongside pacing.

### 7. Remove direct duration editing input
**Where:** `components/AnalysisEditor.tsx` — script phase shot cards
**Problem:** The editable duration input lets artists type arbitrary numbers (e.g. 7s) that may not be valid for the model and break timestamp alignment across the scene.
**Fix:** Show duration as read-only text. The only ways to change shot timing are: pacing selection (regenerates script), split button (divides a shot), or model change (adjusts pacing).

### 8. Send model's nearest valid duration to Segmind
**Where:** `server/routes/generate-video.ts` — generate-video endpoint
**Problem:** `durationSec: shot.duration` sends the raw shot duration. A 6s shot on Veo Fast (8s only) would fail or produce unexpected results.
**Fix:** Pick the smallest model duration >= shot duration. If shot duration > all model durations, use the largest. The full clip is preserved; the render timeline handles trimming/transitions.

## UI

### 9. Custom dropdown component (Windows compatibility)
**Where:** All `<select>` elements in AnalysisEditor.tsx (env picker in script, video model, resolution, aspect ratio)
**Problem:** Native `<select>` renders with OS theme. Mac looks fine (dark popover). Windows shows a white system dropdown that clashes badly with the dark UI.
**Fix:** Build a reusable `<Dropdown>` component using divs + our surface styles. Same behavior, matches dark theme on all platforms.

### 10. Silent failure feedback gaps (Codex audit)
**Where:** Multiple locations in AnalysisEditor.tsx and Storyboard.tsx
**Problems identified by Codex:**
- Blueprint side actions fail silently (upload, re-run analysis, style actions)
- Style exploration has loading states but no failure feedback
- Shot split has no busy state or error display
- Environment edits and delete swallow failures
- Scene lock/unlock has no pending state or visible error
**Fix:** All async actions need: disabled while pending, spinner, error message shown inline. Build a shared pattern first (`useActionFeedback` hook or similar).

### 11. Shared feedback pattern
**Where:** New utility — `hooks/useActionFeedback.ts` + `components/ActionFeedback.tsx`
**Problem:** Every async button reinvents loading/error/success handling. Some do it well (Studio generate), some don't (Blueprint actions). No consistency.
**Fix:** One reusable pattern:
```tsx
const { run, isPending, error, flash } = useActionFeedback();
// Button: disabled={isPending}, shows spinner, shows error/success flash
```
Use in every extraction during the Storyboard breakup.
